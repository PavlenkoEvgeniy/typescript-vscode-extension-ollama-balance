# Ollama Balance

Расширение VS Code, которое показывает в статус-баре, сколько квоты ollama.com cloud у аккаунта ещё осталось. Единственный источник истины — endpoint `GET /api/balance` аккаунта пользователя; расширение ничего не считает и не накапливает само.

## Language

### Показываемое значение

**Остаток (Remaining)**:
Часть квоты, ещё не израсходованная аккаунтом. В долларах, когда API их отдаёт; в процентах — только на legacy-планах, где API отдаёт одну лишь долю.

**Кредиты (Credits)**:
Деньги, которыми измеряется квота на аккаунтах новых планов. Делятся на включённые и купленные.
_Avoid_: баланс (как имя поля), «балланс»

**Включённые кредиты (Included)**:
Кредиты, входящие в план; обновляются по расписанию сброса плана.

**Купленные кредиты (Purchased)**:
Кредиты, докупленные сверх плана; учитываются только непросроченные.

**Период (Period)**:
Интервал, на который выданы включённые кредиты, с границами `from`/`until`. У новых планов он один; у legacy-планов вместо него окна использования.
_Avoid_: окно (для периода новых планов)

**Сброс (Reset)**:
Момент обновления квоты: конец периода у новых планов, `resets_at` окна у legacy.

### Использование

**Доля использования (Usage fraction)**:
Доменная величина: израсходованная доля квоты, число от 0 до 1. Остаток = 1 − доля. Единица измерения всех порогов и раскрасок.
Это понятие домена, а не поле провода. Проводных представлений несколько, и они не совпадают ни единицей, ни полярностью: `usage` — израсходованное, доля 0..1; `remaining_percent` — оставшееся, проценты 0..100. К доменной величине они приводятся ровно один раз, на границе парсинга; сырые проводные значения дальше не ходят.
_Avoid_: называть `usage` или `remaining_percent` «долей использования» без указания, что это провод

**Окно использования (Usage window)**:
Интервал, на который распространяется квота на legacy-планах: месячное (monthly), недельное (weekly), сессия (session). У новых планов окон нет — только период.
_Avoid_: период (для legacy-окон), лимит

**Расход (Spend)**:
Сумма, потраченная за диапазон времени. Статистика, а не квота: приходит из `GET /api/usage` (`totals.usage_usd`) и в остаток не входит.
_Avoid_: окно расходов, activity, cost

### Счёт

**План (Plan)**:
Тариф аккаунта ollama.com (`pro`, `max`, `team`, `free`). Определяет величину включённых кредитов, но расширение её не вычисляет — она приходит из ответа API.
_Avoid_: подписка

**Ключ API (API key)**:
Персональный ключ ollama.com, с которым расширение опрашивает API. Хранится в System SecretStorage VS Code, а не в settings.json.
_Avoid_: токен, сессия

### Состояния

**Деградировавшее состояние (Degraded state)**:
Ключ не установлен / запрос не удался / ответ не разобрался. Ошибка объясняется в tooltip, а последнее известное значение остаётся в статус-баре с пометкой устаревания — кроме случая, когда данных нет вовсе (ключа нет или он отвергнут). Уведомление выводится только один раз при смене состояния.

**Порог (Threshold)**:
Граница по доле использования, при которой элемент меняет цвет: оранжевый при ≥50 %, красный при ≥90 %.

## Внешние зависимости

Домен ollama.com: `GET /api/balance` — документированный источник квоты (включённые и купленные кредиты); `GET /api/usage` — документированная статистика расходов, квот не отдаёт; `POST /api/me` — неофициальный, отдаёт только тариф. Каждый из `balance` и `usage` допускает 10 запросов в минуту на пользователя, причём лимит общий для всех ключей и устройств. Общий ли он между двумя endpoint'ами — документация не говорит.
