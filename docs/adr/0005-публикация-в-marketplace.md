# Публикуем расширение в Visual Studio Marketplace

До сих пор расширение распространялось только через ассеты GitHub-релизов: его надо было найти, скачать и поставить руками, а обновлений оно не приносило вовсе. Решение: публикуемся в Marketplace под издателем `PavlenkoEvgeny` — это единственный канал, дающий автообновление, — а `.vsix` в релизах остаётся запасным путём для тех, кому нужна конкретная версия. Публикация не делает расширение официальным: имя «Ollama Balance» описывает то, что расширение действительно делает (читает API ollama.com), но содержит чужой товарный знак, поэтому оговорка о непричастности стоит и в первом абзаце README, и в описании листинга. Отдельно: GitHub-хендл владельца — `PavlenkoEvgeniy`, через «i», а ID издателя — `PavlenkoEvgeny`, без неё; это не опечатка, а два независимых идентификатора, и «исправлять» их друг под друга не надо.

## Consequences

- Полный ID расширения меняется с `p3s.ollama-balance` на `PavlenkoEvgeny.ollama-balance`. Для VS Code это **другое** расширение: 1.1.2 не обновится до 1.1.3, а встанет рядом. Ключ API не переезжает — `SecretStorage` привязан к ID расширения, — поэтому его надо ввести заново, а старое расширение снять вручную.
- ID издателя и имя расширения резервируются навсегда в момент первой публикации. `unpublish` сохраняет статистику и оставляет расширение находимым через API, а `remove` необратим; номер удалённой версии переиспользовать нельзя, а последнюю версию удалить нельзя.
- Публикация опирается на PAT Azure DevOps, а глобальные PAT перестают работать для Marketplace **1 декабря 2026** — все, включая выпущенные незадолго до этой даты. Замена при этом не назначена: `vsce publish --oidc` в `@vscode/vsce` 4.0.0 уже есть, но на 8 октября 2026 бэкенд Marketplace его не поддерживает и `POST /_apis/gallery/token` отвечает `TrustedPublishingNotSupportedException`, а живая альтернатива `vsce publish --azure-credential` (Entra ID, managed identity) требует ручной настройки в портале Azure. Переезд поэтому идёт на первый из двух путей, который к тому моменту заработает.
- Первая публикация делается руками, а не из CI. Причина не в удобстве: `--oidc` работает только из GitHub Actions и проверить его иначе нечем, а PAT, положенный в секрет workflow, пришлось бы менять вместе с механизмом.
- Канал pre-release не заводится. На нуле установок это лишняя сущность, которую надо не забыть обновить, а завести её можно в любой момент — необратимости здесь нет.
