# Опираемся на неофициальный `GET /api/usage` с защитным парсингом

Официальной документации для `/api/usage` и `POST /api/me` не существует, но оба endpoint'а живы и используются минимум пятью независимыми сторонними проектами (oh-my-pi, onWatch, zcode-acp, openusage, ollama-cloud-watch), которые читают одну и ту же форму ответа. Решение: использовать `GET https://ollama.com/api/usage` с `Authorization: Bearer <ключ>` как источник данных, при этом: парсинг защитный (окна `monthly`/`weekly`/`session` необязательны и зависят от года подписки; числа могут прийти строками; форма ответа может измениться), 401/403 = «ключ недействителен», 404 = endpoint убрали — деградация, никогда не падение. Альтернативы отвергнуты: скрaping web-UI с cookie — хрупко и хуже с точки зрения безопасности; подпись ed25519 по идентификации CLI работает без ключа, но дублирует чужую криптографию и не задокументирована.
